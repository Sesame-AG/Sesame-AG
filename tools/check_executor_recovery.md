# 执行服务断连恢复回归

## 故障链

宿主绑定 CommandService 失败后，旧逻辑只留下待初始化标记；执行门禁直接返回 false，后续任务不会重新连接。重新勾选协议会发送配置重载广播，间接打破停滞。

运行中断连还会使 RPC 在本地门禁处返回空值，被 RequestManager 累计成接口失败，达到阈值后进入无到期时间的离线暂停。

修复在门禁发现断连时合并重连请求，对暂时性绑定失败间隔 15 秒重试。恢复后继续初始化或恢复已有会话的待执行任务，不重启已初始化的业务。重试受账号、会话、协议和离线状态约束。本地执行条件未满足不再累计为远端 RPC 失败；真实空响应和原有风控仍按原规则处理。

## 本地检查

准备 JDK 17，先编译项目以缓存 Kotlin 编译器和协程依赖：

```sh
python3 tools/check_executor_recovery.py
```

脚本抽取实际恢复函数和 RPC 执行函数编译运行；Android/Binder 使用桩，延迟缩短。覆盖延迟连接、并发恢复、已有会话不重复初始化、服务端拒绝、撤回协议、切换会话、离线暂停，以及本地拒绝不计入接口失败。不能替代 Android 生命周期实测。

## 实机检查

先备份配置，确认单台设备已连接且模块当前版本协议已由用户确认。保留已安装 APK 用于回滚，不操作协议勾选。

1. 模块正常初始化后停止模块进程，向宿主发送执行广播，确认出现绑定失败或服务断连。
2. 重新打开模块让服务可用，随后返回桌面息屏。不要发送配置重载广播。
3. 检查宿主自动记录服务恢复；已初始化会话不应再次出现 `Loaded SesameAG`，待执行任务应继续调度。仅有绑定成功不足以确认业务恢复。
4. 检查未因本地断连产生 `rpc_error_threshold`，协议字段和业务配置保持不变。
5. 恢复模块运行并核对后续闹钟。若设备断连导致测试中断，应重新连接后完成清理。

强制停止会设置 Android 的停止标记，不能将“用户强制停止后不打开模块”当作普通进程回收。短时息屏通过不代表跨夜系统冻结或网络故障已验证。原始配置和日志含隐私信息，不提交到仓库。
